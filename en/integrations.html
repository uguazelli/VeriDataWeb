The Symptoms

What happens when integration is built by whoever was available.

01

Manual data entry between systems

Sales closes a deal in Salesforce. Someone copies it into the ERP manually. Two hours later the data is wrong and nobody knows which system to trust.

02

Integration built by whoever was available

A developer built the Shopify-to-warehouse sync in a weekend three years ago. Nobody documented it. It breaks every other month. The person who built it left.

03

Tool sprawl with no ownership

Five different integration tools adopted by five different teams. Zapier, Make, a custom Python script, an old MuleSoft flow, and a vendor webhook nobody configured correctly. Nobody owns the full picture.

04

The integration that slowed the enterprise deal

Your US buyer asked how data moves between your systems. You didn't have a clear answer. Deals slow down when architecture is invisible.

Details

Honest answers.

Do you work with any integration tool or just MuleSoft?

Any tool that fits the architecture. MuleSoft when the complexity justifies the licensing cost. AWS native when the company is already on AWS and the patterns fit. n8n for workflow automation across SaaS tools. The tool selection comes after the architecture design, not before.

We already have integrations running in production that are broken. Can you help?

Yes. A large part of the assessment is mapping what already exists — including what's undocumented and fragile. You get an honest diagnosis of what's risky before we talk about what to build next.

What's the difference between this and hiring an integration developer?

A developer builds what you tell them to build. An architect decides what to build and why. If you already have developers, you probably need the second thing more than the first. If you don't have developers, start there — the advice won't land without someone to implement it.

Do you handle integrations that involve sensitive data or compliance requirements?

Architecture design yes — I know where PII leaks in integration flows, where API keys get exposed, where audit trails break. Formal compliance certification is out of scope. That's a separate engagement.

Can you build the integration, not just design it?

Yes. Architecture-only and architecture-plus-build are both available. The difference is scope and price — implementation projects are fixed-scope, fixed-price engagements. Not open-ended time-and-materials.

We have a broken integration that nobody understands. Can you fix it?

That's one of the most common starting points. Before building anything new, it's worth understanding what actually exists. A fix engagement starts with diagnosis — mapping what's there, what's failing, and why — then stabilizes it.

How quickly can you start?

Typically within 7 days. The practice is deliberately small so each client gets real attention.

Your systems should talk to each other.

They probably can. The architecture just needs to be right first.
